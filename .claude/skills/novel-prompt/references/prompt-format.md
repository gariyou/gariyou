# 完成プロンプトの出力形式

アプリ（AI Novel Prompt Builder）と同じ形式で出力する。形式は3種類。**未入力の項目・空のセクションは出力しない。**

## 冒頭（テンプレート別の役割付け）

小説モード（`mode: "novel"`）:

- フル設計書: 「あなたは長編小説制作に特化した編集者兼プロ作家AIです。」＋「以下の設定資料をもとに、小説制作を進めてください。」
- 企画用: 企画立案に長けた編集者AIとして役割付けし、末尾の「今回の依頼」でコンセプト案3パターン・売りの整理・あらすじ案・弱点と改善案を依頼
- 執筆用: 編集者兼プロ作家AIとして役割付けし、「今回の依頼」で章・シーン構成に従った本文執筆（文体厳守・口調維持・不明点は先に質問）を依頼
- 校正用: 校正・整合性チェック特化AIとして役割付けし、「今回の依頼」で設定矛盾・口調ブレ・伏線漏れ等のチェックを依頼（原稿はプロンプトの直後に貼ると明記）

RPGモード（`mode: "rpg"`）:

- フル企画書: 「あなたはRPG制作に精通したゲームデザイナー兼シナリオライターAIです。」＋「以下の企画資料をもとに、RPGの企画・シナリオ制作を進めてください。」
- 企画用: RPGの企画立案に長けたゲームデザイナーAIとして役割付けし、「今回の依頼」でゲームコンセプト案3パターン（コアループの違いを明記）・参考タイトルと差別化ポイント・メインシナリオのあらすじ案・弱点と改善案を依頼
- シナリオ執筆用: RPGシナリオ執筆に特化したシナリオライターAIとして役割付けし、「今回の依頼」で章・クエスト構成とイベントシーンに従ったシナリオ執筆（システムと矛盾させない・キャラ/モンスターの設定と口調を維持・セリフとト書きを分ける・不明点は先に質問）を依頼
- レビュー用: RPGの企画・シナリオのレビューに特化したゲームデザイナーAIとして役割付けし、「今回の依頼」で設定・システムとの矛盾、ゲームバランス上の懸念、設定ブレ、伏線・謎の回収漏れ、プレイヤー体験を損なう箇所のチェックを依頼（対象はプロンプトの直後に貼ると明記）

## テキスト形式（汎用・デフォルト）

```
（冒頭文）

■ 作品基本情報

- 作品タイトル: ○○
- ジャンル: ○○

■ 主要キャラクター

【キャラクター1：名前】
- 名前: ○○
- 役割: ○○

■ シーン構成

◆ 第一章「○○」

【シーン1：○○】
- シーンタイトル: ○○

■ 厳守事項

- 設定と本文を混同しないこと
- キャラクターの目的と口調を維持すること
- 世界観のルールを破らないこと
- 伏線を忘れないこと
- 説明過多にせず、場面・行動・会話で描写すること
- 不明点がある場合は勝手に確定せず、候補を提示すること
```

- セクション見出しは `■`、複数アイテムは `【キャラクター1：名前】` ブロック
- シーンに所属章があれば `◆ 章タイトル` で章ごとにグルーピングし、シーン内の「所属章」行は省く
- 複数行の値は `- ラベル:` の次行に2スペースインデントで書く
- 厳守事項の6項目は上記の文言のまま必ず末尾に付ける（上の例は小説モード）。RPGモードでは次の6項目を同じく文言のまま付ける:
  - 企画資料とシナリオ本文を混同しないこと
  - ゲームシステムのルールと矛盾する展開を作らないこと
  - キャラクター・モンスターの設定と口調を維持すること
  - 伏線・謎を忘れないこと
  - プレイヤーの選択の余地を奪う演出過多にしないこと
  - 不明点がある場合は勝手に確定せず、候補を提示すること

## Markdown形式（ChatGPT / Cursor 向け）

テキスト形式と同じ構造で、`■`→`##`、アイテム見出し→`###`（章グルーピング時は章が`###`・シーンが`####`）、ラベルを `**ラベル**:` にする。

## XML形式（Claude 向け）

設定資料全体を `<設定資料>` で包み、各セクションを `<作品基本情報>` のようにタイトル名のタグ、各アイテムを `<キャラクター1>` のような連番タグにする。フィールドは `ラベル: 値` の行（`-` や `**` は付けない）。「今回の依頼」「厳守事項」もタグで包む。

```
（冒頭文）

<設定資料>

<作品基本情報>
作品タイトル: ○○
</作品基本情報>

<主要キャラクター>
<キャラクター1>
名前: ○○
</キャラクター1>
</主要キャラクター>

</設定資料>

<厳守事項>
- 設定と本文を混同しないこと
（以下同じ6項目）
</厳守事項>
```
