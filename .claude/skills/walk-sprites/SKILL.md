# 歩行スプライト制作

立ち絵は用意できるが歩行コマが揃わない、という状況を解くためのスキル。
小さなドット絵（1セル48px前後、低頭身）では、画像AIに歩行ポーズを描かせるより、**良い立ち絵のドットをコードで数ドット動かす**ほうが安定する。まずこの方法を試す。

## 進め方

1. **入力を確かめる。** セル寸法、向きの数と並び順、透過の有無を実物から測る。聞けばわかることを推測で決めない。
2. **代表で試す。** 体形や装備が違う2〜3体を選び、難しい向き（斜め後ろ、横）を必ず含める。1体で通っただけの方法を「標準」と呼ばない。
3. **生成する。** `scripts/autowalk.py` を使う（下記）。座標をキャラごとに手で書かない。
4. **自分の目で見る。** 検出結果の重ね画像と、拡大した全コマを開いて確かめる。確かめる項目は「判定」の節。
5. **ユーザーに見せる。** 動くGIFと検出結果を渡し、良し悪しはユーザーが決める。見ていないものを「確認済み」と書かない。
6. **駄目な所だけ直す。** 良いコマは画素単位で保持する。同じ不良が繰り返すなら、指示の追加ではなく方法を見直す。

## autowalk.py

```
python3 scripts/autowalk.py <立ち絵.png> <出力フォルダ>
```

- 入力は1セル48pxの透明PNG。列がキャラ、行が向き（下・左下・左・左上・上・右上・右・右下）。
- 出力は、キャラごとのゲーム用シート（横3コマ×縦8方向、左足・立ち・右足）、検出結果の重ね画像、確認用GIF。
- 再生順は 左足→立ち→右足→立ち。
- 必要なのは Python と Pillow、numpy だけ。

仕組みと限界:

- **脚**は、正面の絵で「左右の脚の間にすき間がある行」を数えて高さを決める。ローブなど脚が短いキャラは動かす量が自動で減る。脚がまったく見えないキャラには使えない。
- **手**は、正面の絵で体の両端にある肌色の塊（なければ手袋）から色を覚え、横向き以外では体の端にある塊だけを手とする。手袋と同じ色の小物（ポーチなど）が隣にあると、動かした跡が崩れる。
- 盾・マント・剣など、裾より下まで垂れる装備があると脚として動いてしまう。重ね画像で必ず確かめる。
- セル寸法や並び順が違う素材は、スクリプト冒頭の `CELL` と `DIRS` を合わせる。

## 動かし方の規則

- 脚の太さは立ち絵のまま変えない。動かすだけにする。
- 正面・背面は片脚を上へ持ち上げる。斜めは前に出す脚を進む向きへ、後ろの脚を逆へ。横は脚の塊を前後へ動かし、奥の脚は一段暗くする。
- 斜めで足を基準線より下へ出さない。脚が交差する歩は小さく、開く歩は大きく動かす。
- 手は前に出た脚と反対側を前へ振る。横向きは前後に2ドット、それ以外は上下に1ドット。斜めで手を横に動かすと体の輪郭が崩れる。
- 「手前／奥」と「キャラ自身の右／左」を混同しない。画面の左右とも別物。
- 細かく切った脚パーツや、平面上での膝曲げは崩れやすい。連続した脚の塊を小さく動かす。

## 判定

数値や検出件数が合っていても、見た目の合格にはならない。次を画像で確かめる。

- 左足コマと右足コマで、前に出る脚が実際に入れ替わっているか。同じ足が2回出ていないか。
- 脚が裾から離れていないか。足元や体の縁に、はみ出した線や欠けがないか。
- 頭・胴・装備が3コマで動いていないか（動かすのは脚と手だけ）。
- 実寸に近い大きさで見て、歩いて見えるか。拡大でしか分からない動きは小さすぎる。
- 明るい背景と暗い背景の両方で、縁や透過に異常がないか。
- 静止コマとループ再生の両方で見る。

確かめた範囲と、確かめていない範囲を分けて報告する。ゲームに入れていないなら、ゲーム内で動くとは言わない。

## 画像AIで描かせる場合

高頭身や大きなセル（256pxなど）で、コードでは動かせない素材に限る。

- ポーズの参照（人形など）と外見の参照（キャラ絵）を、役割を分けて渡す。
- 難しい向きを含む代表方向を先に作り、通ってから残りを作る。
- 反対の足を指示しても同じ足が返ることが多い。前半の相と後半の相を分けて生成する。
- 生成画像は等分グリッドを守らない。実際の空白を測って切り出す。
- 拡縮は同じ生成グループで共通の倍率にし、位置合わせは整数移動で行う。コマごとの拡縮で不整合を隠さない。
- 背景を消すだけの編集でも人物が変わることがある。編集後はポーズも見直す。
- 追加の費用や外部サービスが要るときは、先にユーザーに確かめる。
